# Run doc — 시험노트 (PDF 기반 문제은행, Next.js 16 + Prisma/SQLite)

## Reproduce uncommitted artifacts (fresh checkout)

1. Copy env file from the main checkout:
   - `cp /Users/littlemac/Documents/Codex/2026-09-14/files-pasted-by-the-user-pdf/.env.local .env.local`    - It contains `DATABASE_URL` (SQLite file URL), `GEMINI_API_KEY`, and an optional commented-out `GEMINI_MODEL`. Never commit or print the values.
2. Install dependencies with npm (project uses a `package-lock.json`):
   - `npm install`
3. Create/sync the SQLite database (0-byte `prisma/dev.db` breaks every API route):
   - `set -a; source .env.local; set +a; npx prisma db push --skip-generate`
   - Prisma client generation happens automatically on install; if types are missing run `npx prisma generate`.
4. `next.config.ts` marks `pdfjs-dist` as a `serverExternalPackages` entry. It is required — without it pdf.js's worker dynamic import fails under Turbopack and PDF upload always 500s. Keep it.
5. Optional test asset: `work/pdf-test/text-based-source.pdf` (2-page text PDF used to exercise `/api/documents/upload`).

## Run the server

- Command: `npm run dev` (Next.js 16 dev server, default port **3000**; if 3000 is busy Next picks a random port — check the `Local:` line in the log).
- Interactive/detached-in-shell launch (macOS) — works only when the shell's process group survives:
  `{ nohup npm run dev > "<log>" 2>&1 < /dev/null & echo "pid=$!"; disown; }`
- **Proven background recipe for this workspace (launchd)** — plain `nohup` gets reaped by the command runner, and under `launchctl submit` both the `npm` wrapper and a redirect into `.freebuff/*.log` produced instant exit-1/empty-log respawns. The combination that survives is direct `node` + `/tmp` log:
  ```
  launchctl submit -l probe-tmp-log -- /bin/sh -c 'echo probe-start; cd /Users/littlemac/Documents/Codex/2026-09-14/files-pasted-by-the-user-pdf && exec /opt/homebrew/bin/node node_modules/next/dist/bin/next dev -p 3000 > /tmp/dev-launchd.log 2>&1'
  ```
  - Take the pid from `launchctl print gui/$(id -u)/probe-tmp-log` (grep `pid =`).
  - Stop when done: `launchctl remove probe-tmp-log` (this kills the server too).
- Health check: `curl -s -o /dev/null -w '%{http_code}' http://localhost:3000` → expect `200`.
- Smoke tests:
  - `curl -s -X POST http://localhost:3000/api/documents/upload -F "file=@work/pdf-test/text-based-source.pdf;type=application/pdf"` → JSON with `pageCount` and `extractedCharacterCount`.
  - `curl -s http://localhost:3000/api/question-sets` → saved question-set list.

- LLM note: question generation and subjective grading call the Gemini API from the server; Google-side 503s ("high demand") are transient and surfaced as retryable errors in the UI.   - The top navigation bar (`.topbar`, shared by home and exam) is always pinned: `position: sticky; top: 0; z-index: 60` with a solid background — it never scrolls away. `section[id]` gets `scroll-margin-top: 76px` so anchor links (#upload/#story/#library) land below the bar.
   - Model is set by the quality-first pool (see LLM pool note below); `GEMINI_MODEL` env optionally re-orders it. Flash-tier models get 503-overloaded independently (e.g. `gemini-3.7-flash`/`gemini-3.8-flash` 503 while `gemini-3.5-flash` serves fine); minimal "ping" requests can succeed while generation 503s, so test with a real prompt.   - **Gemini model pool & fallback** (`src/lib/gemini-models.ts`): quality-first pool `gemini-3.8-flash → 3.7 → 3.6 → 3.5 Flash` (IDs verified live via ListModels + real calls on 2026-09-15; `gemini-2.5-pro/flash` 404 "no longer available to new users" on this key → excluded). The manager in `ai.ts` (`completeWithModelPool`) walks the pool: pre-filters via cached ListModels availability, reserves a slot from a conservative per-UTC-day counter (`estimatedRpd: 200` — Google exposes NO official remaining-RPD API for AI Studio keys; `usageMetadata` is never used as quota), and falls back on classified errors: 429 → skip until UTC midnight, 5xx → 60s cooldown (3 attempts with backoff inside `complete()` first), timeout → 30s cooldown, 404/400 → 24h cooldown. Generation response returns `{provider, model, displayName, fallback, fallbackReason}`; the model is persisted on `QuestionSet.generatedModel/Name/Fallback` and shown as a blue pill badge in the exam topbar. Dev-only diagnostics: `GET /api/dev/model-status` (404 outside `next dev`). Optional `GEMINI_MODEL` env re-orders the pool (pinned first) instead of disabling fallback. Verified live: 3.8→503, 3.7→503, 3.6→success with `fallback:true`, badge renders "Gemini 3.6 Flash · Fallback". **OpenRouter second provider** (`src/lib/openrouter-models.ts`, wired into the same manager loop in `ai.ts`): when EVERY Gemini model is unavailable (or GEMINI_API_KEY is unset), the chain falls through to a quality-first OpenRouter free pool — `nemotron-3-ultra-550b-a55b → nemotron-3-super-120b-a12b → thinkingmachines/inkling → gemma-4-31b-it → gemma-4-26b-a4b-it → nemotron-3.5-lightning → inkling-small → ling-3.0-flash-vl` (all `:free` slugs verified against the live catalog 2026-09-16). Catalog (free variant, text output, context ≥100k, response_format support) is cached 5 min; a disappeared/paid model is skipped, never substituted with paid. 429 → 5-min model cooldown, 5xx → 60s, timeout → 30s, 402/404 → 24h; shared free-plan daily budget counter (45, tunable); `openrouter/free` auto-router slot exists but is OFF. Success returns `{provider:'openrouter', model, displayName, fallback:true, fallbackReason:'all_gemini_models_unavailable'}` — exam badge and model-preview already render it. API keys sit together in `.env.local`: `GEMINI_API_KEY` then `OPENROUTER_API_KEY` (empty = OpenRouter skipped). **Model preview badge**: after a successful upload, `GET /api/model-preview` (cached availability + local quota state only — no Gemini calls) tells the user which model the NEXT 문제 생성하기 click will use, rendered as `사용 모델: <name>` in the upload panel; on generation failure the preview re-fetches so the retry shows updated quota state.
