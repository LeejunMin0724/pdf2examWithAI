APPLE-INSPIRED DESIGN GUIDELINES
03. VISUAL DESIGN SYSTEM

Project: PDF-based University Exam Study Web App

==================================================
0. PURPOSE
==================================================

이 문서는 앱의 시각적 디자인을 실제 CSS로 구현할 수 있는 수준까지 정의한다.

01. PRODUCT STRUCTURE는 무엇을 어디에 배치할지,
02. USER EXPERIENCE는 사용자가 어떻게 경험할지를 정의했다.

03. VISUAL DESIGN SYSTEM은
폰트, 색상, 크기, 간격, radius, border, shadow,
component appearance, responsive typography 등을 정의한다.

핵심 방향:

Apple-inspired
+ modern education SaaS
+ content-first
+ quiet / precise / readable

Apple의 시각적 언어를 그대로 복제하지 않는다.
Apple HIG의 원칙을 웹앱에 맞게 번역한다.

핵심 원칙:

- Content first
- Typography-led hierarchy
- Restrained color
- Generous whitespace
- Familiar controls
- Minimal decoration
- Flat content areas
- Materials only where useful
- Responsive by default
- Accessibility by default

==================================================
25. ICONS
==================================================

Icon은 의미 전달을 위해 사용한다.

장식적인 icon을 과도하게 추가하지 않는다.

가능하면 하나의 icon style을 일관되게 사용한다.

Icon만으로 중요한 의미를 전달하지 않는다.
필요하면 text label을 함께 제공한다.


==================================================
26. MATERIAL / GLASS
==================================================

Glassmorphism을 기본 디자인으로 사용하지 않는다.

Liquid Glass 또는 translucent material은
navigation / floating controls 등
UI layer에 제한적으로 사용할 수 있다.

Content layer:

Question
Answer
Explanation
Results

에는 기본적으로 사용하지 않는다.

핵심 원칙:

UI floats.
Content stays clear.


==================================================
27. RESPONSIVE TYPOGRAPHY
==================================================

큰 제목은 clamp()를 활용해
화면 폭에 따라 자연스럽게 변할 수 있다.

예:

font-size:
clamp(40px, 5vw, 60px);

Exam question:

font-size:
clamp(19px, 1.4vw, 22px);

단, 작은 화면에서
읽기 어려울 정도로 글자를 축소하지 않는다.


==================================================
28. RESPONSIVE BREAKPOINTS
==================================================

권장 기준:

Mobile:
< 640px

Tablet:
640px ~ 1023px

Desktop:
>= 1024px

필요하면 실제 content width에 따라
추가 breakpoint를 사용할 수 있다.

breakpoint 자체를 목표로 삼지 않는다.
레이아웃이 깨지는 지점에서 적절히 변경한다.


==================================================
29. MOBILE RULES
==================================================

Mobile:

- single column 우선
- horizontal overflow 금지
- text clipping 금지
- button overflow 금지
- 충분한 touch target
- page padding 약 16px
- Exam content width 100%
- 긴 한국어/영문 혼합 문장 자연스럽게 wrapping

고정 pixel width를 남발하지 않는다.


==================================================
30. DARK MODE
==================================================

Dark mode를 구현할 경우
색상 값을 단순 반전하지 않는다.

Dark background와 text hierarchy를
별도의 semantic token으로 관리한다.

예:

--background-dark
--surface-dark
--text-primary-dark
--text-secondary-dark
--border-dark

다크모드에서도
accent / success / error의 contrast를 확인한다.


==================================================
31. ACCESSIBILITY VISUAL RULES
==================================================

필수:

- 충분한 contrast
- visible focus state
- color-only indication 금지
- 충분한 text size
- text scaling 대응
- touch target 확보
- reduced motion 대응

텍스트가 작아지는 대신
레이아웃이 더 길어지는 것을 허용한다.


==================================================
32. CSS TOKEN PRINCIPLE
==================================================

반복되는 디자인 값은
CSS variable로 관리한다.

예:

var(--text-primary)
var(--accent)
var(--radius-md)
var(--space-4)

같은 값을 여러 component에
직접 hardcode하지 않는다.

디자인 변경이 필요할 때
하나의 token을 수정하여
전체 UI가 일관되게 변경되도록 한다.


==================================================
33. VISUAL PRIORITY
==================================================

시각적 강조 순서:

1. Main Content
2. Primary Action
3. Supporting Content
4. Secondary Action
5. Metadata

UI decoration은
이 hierarchy보다 중요해지면 안 된다.


==================================================
34. FINAL VISUAL PRINCIPLE
==================================================

이 디자인 시스템의 목표는
"애플처럼 보이는 것"이 아니다.

사용자가 화면을 봤을 때:

무엇이 중요한지
→ 무엇을 읽어야 하는지
→ 무엇을 눌러야 하는지

가 자연스럽게 이해되도록 만드는 것이다.

Apple-inspired visual design의 핵심은
색상이나 glass 효과가 아니라
타이포그래피, 여백, 계층, 정렬,
절제된 색상, 익숙한 component,
그리고 세부적인 상태 처리의 일관성이다.
